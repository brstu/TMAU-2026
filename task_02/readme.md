# Общее задание #
Написать модульные тесты для программы, разработанной в лабораторной работе №1, предварительно расширив её математический и функциональный базис.

1. Использовать следующий фреймворк для модульного тестирования — [Google Test](https://github.io).
2. **Анализ устойчивости систем:** Для выбранных линейных дискретных моделей (из блока 1 ЛР №1) аналитически определить критерий устойчивости (найти корни характеристического уравнения на Z-плоскости). В исходном коде программы реализовать логическую проверку: если заданные пользователем коэффициенты $a_i$ приводят к расходящемуся (неустойчивому) процессу, программа должна выводить предупреждение в консоль перед началом симуляции.
3. Исходный код модифицированной программы (включая модуль анализа устойчивости) разместить в каталоге: **trunk\as0xxyy\task_02\src**.
4. Написать модульные тесты для основных функций программы согласно своему варианту, а также для разработанного модуля анализа устойчивости. Разместить тесты в каталоге: **trunk\as0xxyy\task_02\test**.
5. **[Локальная автоматизация]:** Создать в корне проекта командный файл Windows (**`run_tests.bat`**). Этот файл должен автоматически компилировать проект, запускать модульные тесты на локальном компьютере и генерировать отчет о прохождении тестов. 
6. В файле `readme.md` отразить количество написанных тестов и процент покрытия кода тестами (использовать любой инструмент для анализа покрытия, например, [gcovr](https://gcovr.com) или LCOV).
7. Отразить выполнение работы в общем файле [`readme.md`](https://github.com).
8.  Архитектурное требование к тестам: для проверки расчета шагов симуляции использовать **параметризованные тесты (`TEST_P`)** в Google Test, чтобы протестировать сходимость алгоритмов при различных входных наборах данных без дублирования кода.
9. Использовать mock-объекты (**Google Mock**) или подмену входных сигналов для тестирования различных режимов управления (ступенчатый, импульсный, гармоническое воздействие).

## Task 2. Advanced Unit Testing & Code Coverage (Extended Version)

The goal of this task is to implement a predictive stability analyzer for the mathematical models and ensure total software reliability using industrial testing and coverage frameworks executed locally via automation scripts.

---

<details>
  <summary> <b>Рекомендуемые сценарии для тест-кейсов (What to test)</b></summary>

<br>

При написании модульных тестов студенты должны покрыть как минимум три следующих сценария для своих моделей и нового аналитического модуля:

1. **Тестирование на правильность выдаваемых значений моделью: (основной рекомендуемый)**
   * Вручную посчитать выдаваемые значения моделью.
   * Проверка, что при заведомо известных коэффициентах модель возвращает заранее известные значения.
2. **Тестирование модуля анализа устойчивости:**
   * Верификация логики модуля предупреждений: проверка граничных значений Z-плоскости ($|z| = 1$).
   * Проверка, что при заведомо устойчивых коэффициентах (например, для модели 1.1 при $|a| < 1$) метод анализа возвращает `true`.
   * Проверка, что при критических (расходящихся) параметрах (например, $|a| > 1$) метод возвращает `false` и программа успешно выдает предупреждение / генерирует исключение.
2. **Тесты граничных значений нелинейностей (Boundary Value Testing):**
   * Для модели насыщения (Model 2.2): проверка точек $u = U_{max}$ и $u = U_{min}$.
   * Для зоны нечувствительности (Model 2.3): проверка точек $u = \delta$ и $u = -\delta$.
3. **Тесты инвариантов и физического смысла:**
   * Проверка, что при нулевом входном сигнале $u=0$ и нулевом начальном состоянии $y=0$ система находится в состоянии покоя.
   * Проверка правильности шага интегрирования по методу Эйлера (Блок 3) — сравнение с аналитическим решением.

Примерное содержимое `.bat` файла для сборки проекта через CMake и запуска тестов (можно адаптировать под свою структуру папок):

```batch
@echo off
echo =======================================
echo  Compiling project and running tests...
echo =======================================

if not exist build mkdir build
cd build

cmake .. -G "MinGW Makefiles"
cmake --build .

echo =======================================
echo  Running Google Test...
echo =======================================
ctest --output-on-failure

cd ..
pause
```
