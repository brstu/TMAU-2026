# Общее задание

Написать модульные тесты для программы, разработанной в лабораторной работе
№1, предварительно расширив её математический и функциональный базис.

1. Использовать следующий фреймворк для модульного тестирования —
   [Google Test](https://github.com/google/googletest).
2. **Анализ устойчивости систем:** для выбранных линейных дискретных моделей
   (из блока 1 ЛР №1) аналитически определить критерий устойчивости (найти
   корни характеристического уравнения на Z-плоскости). В исходном коде
   программы реализовать логическую проверку: если заданные пользователем
   коэффициенты $a_i$ приводят к расходящемуся (неустойчивому) процессу,
   программа должна выводить предупреждение в консоль перед началом
   симуляции.
3. Исходный код модифицированной программы (включая модуль анализа
   устойчивости) разместить в каталоге: **trunk\as0xxyy\task_02\src**.
4. Написать модульные тесты для основных функций программы согласно своему
   варианту, а также для разработанного модуля анализа устойчивости.
   Разместить тесты в каталоге: **trunk\as0xxyy\task_02\test**.
5. **[Локальная автоматизация]** Создать в корне проекта командный файл
   Windows (**`run_tests.bat`**). Этот файл должен автоматически компилировать
   проект, запускать модульные тесты на локальном компьютере и генерировать
   отчёт о прохождении тестов.
6. В файле `readme.md` отразить количество написанных тестов и процент
   покрытия кода тестами (использовать любой инструмент для анализа покрытия,
   например [gcovr](https://gcovr.com) или LCOV).
7. Отразить выполнение работы в общем файле `readme.md`.
8. Архитектурное требование к тестам: для проверки расчёта шагов симуляции
   использовать **параметризованные тесты (`TEST_P`)** в Google Test, чтобы
   протестировать сходимость алгоритмов при различных входных наборах данных
   без дублирования кода.
9. Использовать mock-объекты (**Google Mock**) или подмену входных сигналов
   для тестирования различных режимов управления (ступенчатый, импульсный,
   гармоническое воздействие).
