## Вариант 7

Задача — дополнить программу из первой работы проверкой сходимости процесса
перед расчётом и покрыть её модульными тестами на Google Test и Google Mock.
Сборку, прогон тестов и замер покрытия выполняет командный файл run_tests.bat.

Исходники моделей первой работы в каталог task_02 не копировались: CMake
подключает их напрямую из соседней папки task_01/src. Модели варианта:

```text
1.7  объект с памятью по входу:
     y[t+1] = a*y[t] + b1*u[t] + b2*u[t-1] + b3*u[t-2]

2.9  вход проходит через корень со знаком:
     y[t+1] = a*y[t] + b*sign(u[t])*sqrt(|u[t]|)

3.1  свободное затухание dy/dt = -a*y, явная схема Эйлера с шагом dt:
     y[t+1] = (1 - a*dt)*y[t],  начальное значение y0
```

## 1. Расположение полюсов

Дискретная система сходится, когда её спектральный радиус — наибольший
модуль полюса, далее ρ — меньше единицы. При ρ, равном единице, процесс
не затухает, а при ρ больше единицы растёт без ограничения.

**Модель 1.7.** Z-преобразование при нулевых начальных условиях даёт
передаточную функцию

```text
            b1*z^2 + b2*z + b3
W(z)  =  ------------------------
               z^2 * (z - a)
```

Знаменатель имеет двукратный нулевой полюс, который появляется из-за
задержек входа на один и два такта, и полюс, равный a. Нулевой полюс
всегда лежит внутри круга, значит ρ равен модулю a, и сходимость решает
только этот коэффициент. Коэффициенты при прошлых входах на неё не влияют.
Для значений по умолчанию (a = 0.6) получаем ρ = 0.6, процесс сходится,
а при ступеньке выход стремится к (0.5 + 0.3 + 0.2) / (1 − 0.6) = 2.5.

**Модель 2.9.** Нелинейность стоит только на входе, собственное движение
линейно: y[t+1] = a·y[t]. Полюс один и равен a, процесс сходится,
пока модуль a меньше единицы.

**Модель 3.1.** Здесь роль играет не только сам объект, но и шаг
интегрирования. Полюс разностной схемы равен 1 − a·dt, и схема сходится,
когда произведение a·dt лежит строго между нулём и двумя. Получить
расходимость можно двумя путями: взять отрицательное a (неустойчив сам
объект) или слишком крупный шаг, при a·dt больше двух (тогда выход
колеблется со сменой знака и нарастает).

Итог по трём моделям:

* 1.7 — полюса 0, 0 и a; ρ равен модулю a; сходится при модуле a меньше 1;
* 2.9 — полюс a; ρ равен модулю a; то же условие;
* 3.1 — полюс 1 − a·dt; сходится при 0 < a·dt < 2.

## 2. Что добавлено в программу

```text
task_02/
├── CMakeLists.txt          опция AS06714_COVERAGE включает gcov
├── run_tests.bat
├── doc/readme.md
├── src/
│   ├── PoleAnalysis.h/.cpp  полюса, спектральный радиус, вердикт, предупреждение
│   ├── Excitation.h/.cpp    интерфейс воздействия и обёртка над функцией из ЛР №1
│   ├── Runner.h/.cpp        прогон модели через интерфейсы Model и Excitation
│   └── main.cpp             диалог с пользователем
└── test/
    ├── test_lab1_models.cpp
    ├── test_pole_analysis.cpp
    └── test_excitation_mock.cpp
```

**Модуль PoleAnalysis** (пространство имён stability). Для каждой модели
своя функция inspectModel возвращает отчёт: список полюсов, знаменатель
передаточной функции, спектральный радиус и вердикт — Converging,
Marginal или Diverging. Полюс считается лежащим на окружности, если ρ
отличается от единицы меньше чем на 1e-9. Нечисловые коэффициенты
(NaN, бесконечность) всегда дают Diverging. Функция printAlarm печатает
предупреждение, enforceConvergence бросает исключение DivergenceError.

**Интерфейс Excitation.** В первой работе вход задаётся свободной
функцией getInputValue, и подменить её в тесте нельзя. Поэтому появился
абстрактный класс Excitation и его реализация LabExcitation, которая
вызывает ту же функцию и умножает результат на амплитуду. Функция
simulateSteps знает только про Model и Excitation, поэтому в тестах
обе стороны заменяются mock-объектами.

**Работа программы.** Пользователь выбирает модель и вводит коэффициенты
(Enter оставляет значение по умолчанию). Сразу после ввода печатаются
полюса и ρ. Если процесс не сходится, появляется предупреждение, и
программа спрашивает, продолжать ли:

```text
  Transfer function denominator: z^2 * (z - 1.3)
  Poles: 0 0 1.3
  Spectral radius = 1.3, verdict: DIVERGING
!!! Stability alarm for Linear_1_7: denominator z^2 * (z - 1.3), spectral radius 1.3 -> DIVERGING
  The process will not settle. Simulate anyway? [y/N]:
```

Затем выбираются вид воздействия, амплитуда и число тактов. Таблица
выводится в консоль и записывается в файл as06714_trace.csv. Программа
работает в цикле, для выхода нужно ввести 0.

## 3. Запуск

Понадобятся CMake 3.16 или новее, компилятор C++17 и Git: Google Test
скачивается во время конфигурации. Для отчёта о покрытии нужны MinGW GCC
и пакет gcovr (pip install gcovr).

Скрипт run_tests.bat собирает проект в папке build_tests, запускает ctest
и сохраняет рядом журнал тестов tests_log.txt, отчёт JUnit tests_junit.xml,
сводку покрытия coverage_summary.txt и подробный HTML-отчёт в папке
coverage. Если компилятор не GCC, тесты всё равно выполняются, а замер
покрытия пропускается.

## 4. Тесты

### 4.1. Ручной расчёт трёх тактов

Начальное состояние нулевое (у модели 3.1 начальное значение 1),
амплитуда входа 1.

Модель 1.7, коэффициенты a = 0.6, b1 = 0.5, b2 = 0.3, b3 = 0.2:

* импульс: y1 = b1 = 0.5; y2 = 0.6·0.5 + 0.3 = 0.6; y3 = 0.6·0.6 + 0.2 = 0.56;
* ступенька: 0.5, затем 1.1, затем 1.66;
* синусоида (первый отсчёт равен нулю): y2 = 0.5·sin 1,
  y3 = 0.6·y2 + 0.5·sin 2 + 0.3·sin 1 ≈ 0.959531.

Модель 2.9, a = 0.5, b = 2:

* ступенька: 2, 3, 3.5;
* импульс: 2, 1, 0.5;
* синусоида: y3 = 0.5·2·√(sin 1) + 2·√(sin 2) ≈ 2.824459.

Модель 3.1, a = 1, dt = 0.1, начальное значение 1: 0.9, 0.81, 0.729 —
при любом входе, потому что вход в уравнение не входит.

Все девять чисел проверяет один параметризованный тест HandCalculation
(TEST_P вместе с ValuesIn), без повторения кода для каждой модели.

### 4.2. Состав тестов

Файл test_lab1_models.cpp, 34 теста:

* HandCalculation (параметризованный, 9) — значения из пункта 4.1;
* InputHistory (2) — отклик модели 1.7 на импульс по очереди показывает
  b1, b2 и b3; вход забывается через два такта;
* SignedRoot (параметризованный, 7) и SignedRootSymmetry (1) — граничные
  точки нелинейности: ноль, плюс и минус единица, модуль входа меньше
  и больше единицы; нечётность корня со знаком;
* EulerDecay (5) — точное решение разностной схемы y0·(1 − a·dt)^n,
  приближение к экспоненте с первым порядком по шагу, независимость
  от входа, возврат к начальному значению после reset;
* SettlingValue (параметризованный, 6) — пределы при длинной ступеньке
  для всех трёх моделей при разных коэффициентах;
* Invariants (4) — покой при нулевом входе и состоянии, суперпозиция
  для 1.7, пропорциональность начальному значению для 3.1, сброс истории.

Файл test_pole_analysis.cpp, 39 тестов:

* UnitCircleEdge (параметризованный, 10) — радиус внутри круга, на
  окружности с учётом допуска, снаружи, а также NaN и бесконечность;
* SpectralRadius (1) — максимум модуля, пустой список, NaN;
* Linear17Poles (параметризованный, 7) — полюса 0, 0, a для семи значений a;
* Sqrt29Poles (параметризованный, 6) — полюс a и все три вердикта;
* Decay31Poles (параметризованный, 6) — обычное и колебательное
  затухание, граница при a·dt = 2 и при a = 0, крупный шаг, отрицательное a;
* NonFinite и ReportText (2) — некорректные коэффициенты, тексты отчёта;
* Alarm и Enforce (4) — молчание при сходимости, предупреждение при
  расходимости и на границе, исключение;
* Lab1Agreement и Behaviour (3) — совпадение с методами isStable из
  первой работы, затухание или рост свободного движения после импульса.

Файл test_excitation_mock.cpp, 12 тестов:

* LabExcitationTest (4) — ступенька, импульс и синусоида с амплитудой,
  неизвестный вид воздействия;
* RunnerWithFakes (3) — mock-модель FakePlant и mock-воздействие
  FakeExcitation: порядок вызовов reset, sample, calculateNext; пустой горизонт;
* ControlModes (5) — ступенчатый, импульсный и гармонический режимы
  подаются через FakeExcitation в настоящие модели; модель 3.1 не реагирует
  на вход; подменённый сигнал даёт тот же результат, что и настоящий.
