## 2. Модели варианта

Модели и входные сигналы не копировались в `task_02`: CMake берёт их
исходники из `../../task_01/src`, поэтому тесты проверяют именно ту

внутри репозитория, где `task_01` и `task_02` лежат рядом.

| Модель | Тип | Уравнение |
| :--- | :--- | :--- |
| Model 1.5 | линейная, запаздывание по состоянию | $y_{\tau+1} = a_1 y_\tau + a_2 y_{\tau-k} + b u_\tau$ |
| Model 2.9 | нелинейная, корневая модуляция входа | $y_{\tau+1} = a y_\tau + b \sqrt{\lvert u_\tau \rvert}\,\mathrm{sign}(u_\tau)$ |
| Model 3.3 | ДУ первого порядка, метод Эйлера | $y_{\tau+1} = y_\tau + \Delta t\,(-a y_\tau + b u_\tau)$ |

Входные воздействия: ступенька $u_\tau = A$, импульс $u_0 = A$, $u_{\tau>0} = 0$,
гармоника $u_\tau = A\sin\tau$.

## 3. Анализ устойчивости

Для каждой модели рассматривается свободное движение ($u = 0$),
к нему применяется Z-преобразование и находятся корни характеристического
уравнения. Модель асимптотически устойчива, если все корни лежат строго
внутри единичной окружности: $\max|z_i| < 1$. При $\max|z_i| = 1$ процесс
не затухает (граница устойчивости), при $\max|z_i| > 1$ — расходится.

### 3.1. Model 1.5

$$y_{\tau+1} - a_1 y_\tau - a_2 y_{\tau-k} = 0 \;\xrightarrow{\;Z\;}\; z^{k+1} - a_1 z^{k} - a_2 = 0$$

Степень уравнения равна $k+1$, поэтому при $k \ge 2$ корни ищутся численно
методом Дюрана–Кернера (функция `polynomialRoots`).

При $k = 1$ получается квадратное уравнение $z^2 - a_1 z - a_2 = 0$,
для которого критерий Джури даёт условия в явном виде:

$$|a_2| < 1, \qquad 1 - a_1 - a_2 > 0, \qquad 1 + a_1 - a_2 > 0.$$

Он реализован в функции `juryCriterionK1` и используется в тестах для
сверки с численным поиском корней. Для любого $k$ достаточным условием
устойчивости является $|a_1| + |a_2| < 1$, необходимым — $a_1 + a_2 < 1$.

Примеры: $z^3 - 0.5z^2 - 0.3 = 0$ (значения по умолчанию) — $\max|z| \approx 0.884$,
устойчива; $z^2 - 0.5z - 0.5 = (z-1)(z+0.5)$ — корень $z = 1$, граница;
$z^4 - 1.2z^3 - 0.5 = 0$ — $\max|z| \approx 1.387$, неустойчива.

### 3.2. Model 2.9

Нелинейность действует только на вход, однородная часть линейна:
$y_{\tau+1} = a y_\tau$, характеристическое уравнение $z - a = 0$, корень $z = a$.
Условие устойчивости: $|a| < 1$.

### 3.3. Model 3.3

Разностная схема Эйлера: $y_{\tau+1} = (1 - a\Delta t)\,y_\tau$, корень
$z = 1 - a\Delta t$. Условие $|1 - a\Delta t| < 1$ равносильно $0 < a\Delta t < 2$.
Если шаг слишком большой ($a\Delta t > 2$), схема расходится даже для
устойчивого объекта; при $a < 0$ неустойчив сам объект.

### 3.4. Реализация

Модуль `StabilityAnalyzer` (`src/StabilityAnalyzer.h/.cpp`):

| Функция | Назначение |
| :--- | :--- |
| `polynomialRoots(coeffs)` | все корни полинома методом Дюрана–Кернера |
| `classify(maxModulus)` | вердикт `Stable` / `Boundary` / `Unstable`; $\lvert\,\lvert z\rvert - 1\rvert \le 10^{-7}$ считается границей |
| `analyzeModel1_5`, `analyzeModel2_9`, `analyzeModel3_3` | анализ конкретной модели, возвращает вердикт, $\max\lvert z\rvert$ и текст уравнения |
| `juryCriterionK1(a1, a2)` | аналитический критерий для Model 1.5 при $k = 1$ |
| `isStable(result)` | `true` только при асимптотической устойчивости |
| `warnIfUnstable(name, result, out)` | печатает предупреждение в поток |
| `requireStable(name, result)` | бросает `UnstableSystemError` для неустойчивой модели |

Коэффициенты `NaN` и бесконечность считаются неустойчивыми.
В `main.cpp` анализ выполняется **до начала симуляции**. Пример вывода
при $a_1 = 1.2$, $a_2 = 0.5$, $k = 3$:

```
Characteristic equation: z^4 - (1.2)*z^3 - (0.5) = 0
Largest root modulus: 1.38728
[WARNING] Model_1_5: z^4 - (1.2)*z^3 - (0.5) = 0, max |z| = 1.38728. Root outside the unit circle, the process DIVERGES!
```

Программа запрашивает номер модели и её коэффициенты, выводит
характеристическое уравнение и наибольший модуль корня, затем — сигнал,
амплитуду и число шагов. Результат печатается таблицей и сохраняется
в CSV-файл `<модель>_<сигнал>.csv`.

Для тестирования с mock-объектами цикл симуляции вынесен в функцию
`runSimulation(Model&, const InputSignal&, steps)` (`src/Simulator.*`).
Она работает только через абстрактные интерфейсы, поэтому вместо модели
и сигнала можно подставить mock.

## 5. Сборка и запуск

Требования: CMake ≥ 3.21, компилятор C++17 (для покрытия — MinGW GCC),
доступ к GitHub при первой сборке (Google Test скачивается CMake),
Python с `gcovr` для отчёта покрытия (`py -m pip install gcovr`).

```bat
run_tests.bat
```

Скрипт находит CMake и компилятор, собирает проект с флагами
`--coverage`, запускает `ctest` и сохраняет:

- `test_report.txt` — консольный вывод тестов;
- `test_report.xml` — отчёт JUnit;
- `coverage_report.txt` и `coverage.html` — покрытие кода (gcovr).

Ручной запуск:

```bat
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

## 6. Модульные тесты

### 6.1. Ручной расчёт значений

Три шага из нулевого состояния, $A = 1$.

**Model 1.5** ($a_1 = 0.5$, $a_2 = 0.3$, $b = 1$, $k = 1$), ступенька:
$y_1 = 1$, $y_2 = 0.5 \cdot 1 + 0.3 \cdot 0 + 1 = 1.5$,
$y_3 = 0.5 \cdot 1.5 + 0.3 \cdot 1 + 1 = 2.05$.

**Model 2.9** ($a = 0.7$, $b = 1$), ступенька:
$y_1 = 1$, $y_2 = 0.7 + 1 = 1.7$, $y_3 = 1.19 + 1 = 2.19$.

**Model 3.3** ($a = 1$, $b = 1$, $\Delta t = 0.1$), ступенька:
$y_1 = 0.1$, $y_2 = 0.1 + 0.1 \cdot 0.9 = 0.19$, $y_3 = 0.19 + 0.1 \cdot 0.81 = 0.271$.
